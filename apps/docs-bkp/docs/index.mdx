# HyperDev

**HyperDev** is a CLI toolkit for **Hyper Coding** — a methodology that treats AI-assisted development as an engineering discipline, not a guessing game.

Here's the actual problem: AI coding agents don't fail because the models are bad. They fail because the feedback loops are broken. Code gets generated without guardrails, context drifts, errors compound quietly, and nobody notices until the mess is too deep to untangle. Hyper Coding fixes that by automating the feedback loops that good engineers already run manually — just consistently, and without relying on memory.

## The 5 Principles

<CardGroup cols={2}>
  <Card title="Deterministic First" icon="lock">
    Anything that can be done deterministically should not use an LLM. Templates, scaffolding, and known transformations are predictable — keep them that way.
  </Card>
  <Card title="Engineered Friction" icon="shield">
    Intentionally increase the effort required for complex solutions. Make simplicity the path of least resistance by structuring planning workflows that force the right questions upfront.
  </Card>
  <Card title="Reactive Context" icon="bolt">
    Automate context engineering. Provide the right context at the right time — watching file changes, tracking architecture state, and feeding it to the agent continuously.
  </Card>
  <Card title="Tools Integration" icon="wrench">
    Give your AI agent the same external advantages you have. Linters, security scanners, architecture validators — agents should run these too, not just humans.
  </Card>
  <Card title="Real-time Feedback" icon="gauge">
    Provide feedback as soon as possible. The longer an agent runs without feedback, the more compounding errors accumulate. Interrupt early, correct often.
  </Card>
</CardGroup>

## Installation

```bash
bun add -g @hypercli/cli
```

Verify the install:

```bash
hyper --version
```

## The Toolkit

Everything runs under the single `hyper` CLI. Each tool targets one of the five principles.

<AccordionGroup>
  <Accordion title="hyper gen — Code Generation" icon="code">
    **Principle: Deterministic First**

    **Status: Available**

    Generate code using kits, recipes, and [Jig](https://jig.saulo.engineer) templates. `hyper gen` keeps deterministic work deterministic — scaffolding runs from versioned templates, not ad-hoc LLM output.

    - Install kits from any source: `hyper kit install <source>`
    - Run a recipe: `hyper run <kit> <recipe>`
    - Templates use Jig syntax (`.jig` files) with an optional `@ai` tag for the parts that genuinely need generation
    - Recipes are composable YAML workflows with 13 tool types: template, action, shell, ai, patch, and more

    <Card title="hyper gen docs" icon="arrow-right" href="/tools/gen" />
  </Accordion>

  <Accordion title="hyper plan — Define → Design → Decompose → Develop" icon="map">
    **Principle: Engineered Friction**

    A structured planning workflow that forces the right questions before you write a line of code. `hyper plan` walks through four stages — Define the problem, Design the solution, Decompose into tasks, then Develop — making it harder to skip steps and easier to stay on scope.

    <Card title="hyper plan docs" icon="arrow-right" href="/tools/plan" />
  </Accordion>

  <Accordion title="hyper watch — Always-on Agent Whisperer" icon="eye">
    **Principle: Reactive Context**

    A background daemon that watches your codebase and injects the right context into your agent at the right moment. File changes, architecture violations, dependency updates — `hyper watch` catches them and surfaces them automatically, so you don't have to babysit the context window.

    <Card title="hyper watch docs" icon="arrow-right" href="/tools/watch" />
  </Accordion>

  <Accordion title="hyper tools — Swiss Army Knife" icon="toolbox">
    **Principle: Tools Integration**

    Sets up and integrates the external tooling your agent needs: linters, security scanners, AI tools, architecture validators. Agents shouldn't be flying blind on code quality — `hyper tools` wires up the same feedback instruments you rely on.

    <Card title="hyper tools docs" icon="arrow-right" href="/tools/tools" />
  </Accordion>

  <Accordion title="hyper dash — Real-time Dashboard" icon="chart-bar">
    **Principle: Real-time Feedback**

    A monitoring dashboard for multi-agent workflows. See what's running, what's failing, and what needs intervention — in real time, not after the fact.

    <Card title="hyper dash docs" icon="arrow-right" href="/tools/dash" />
  </Accordion>
</AccordionGroup>

<Note>
  **hyper hq** is a bonus operational tool for managing Claude Code sessions via tmux and Telegram. It's not a Hyper Coding principle — it's session infrastructure. [Learn more →](/tools/hq)
</Note>

## Quick Start

<Steps>
  <Step title="Install">
    ```bash
    bun add -g @hypercli/cli
    ```
  </Step>
  <Step title="Install a kit">
    ```bash
    hyper kit install nextjs
    ```
  </Step>
  <Step title="Generate code">
    ```bash
    hyper run nextjs crud --name Post
    ```
  </Step>
</Steps>
