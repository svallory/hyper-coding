## Global Options

These options apply to all commands:

| Flag | Description |
|------|-------------|
| `--debug` | Enable debug logging |
| `--verbose` | Enable verbose output |
| `--config=<path>` | Use specific config file |

## Parameter Types

| Type | Description | CLI Format |
|------|-------------|-----------|
| `string` | Plain string | `--name=MyComponent` |
| `boolean` | True/false | `--typescript=true`, `--tests=false` |
| `JSON string` | Complex objects | `--config='{"strict":true}'` |
| `JSON array` | Array values | `--options='["async","export"]'` |
| `@file` | File-based input | `--config=@schema.json` |

Alternate space-separated format is also accepted: `hyper gen create-api --name UserAPI --method GET`

## Action Resolution Order

When `hyper gen <name>` is invoked:

1. Registered action by exact name
2. Recipe file with that name (`.yml` extension added if missing)
3. Auto-discovery: searches `.hyper/kits/<name>.yml`

## Recipe Validation Checks

- YAML syntax correctness
- Required fields presence (`name`, `steps`, `variables`)
- Variable type definitions and constraints
- Step dependency validity and circular references
- Tool availability and configuration
- Template file references
- Sub-recipe existence


## CI/CD Integration

```yaml
# .github/workflows/validate-templates.yml
name: Validate Templates
on: [push, pull_request]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: oven-sh/setup-bun@v1

      - name: Install HyperDev
        run: bun install -g hyper

      - name: Validate Templates
        run: |
          find recipes/ -name "template.yml" -exec hyper template validate {} \;

      - name: Validate Recipes
        run: |
          find recipes/ -name "*.yml" -path "*/recipes/*" -exec hyper recipe validate {} \;
```

## Template Organization Conventions

```
recipes/
├── components/
│   ├── react-component/
│   │   ├── template.yml
│   │   └── templates/
│   └── vue-component/
├── api/
│   ├── express-endpoint/
│   └── fastapi-endpoint/
└── recipes/
    ├── fullstack-app.yml
    └── microservice.yml
```

Naming conventions:
- **Actions**: `verb-noun` (e.g., `create-component`, `update-schema`)
- **Templates**: `technology-type` (e.g., `react-component`, `express-api`)
- **Recipes**: descriptive name (e.g., `fullstack-app`, `microservice-setup`)
- **Parameters**: `camelCase` (e.g., `componentName`, `apiEndpoint`)
