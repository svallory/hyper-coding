## Code of Conduct

A few basic rules that keep the community useful:

- **Be direct, not harsh.** Feedback should help, not score points.
- **Welcome beginners.** Everyone was new once.
- **Stay on topic.** This is a developer tools community — keep discussions relevant.
- **Ship complete work.** Half-finished PRs and templates waste reviewers' time.
- **Document what you build.** Code without docs is harder to use.

If someone's being a problem, report it via GitHub or DM a maintainer on Discord.

## Contribution standards

Code and template contributions go through PR review. The short version of what reviewers look for:

- Tests for new behavior
- No regressions on existing tests (`bun test`)
- Jig syntax in templates (not EJS)
- Conventional commit messages (`feat(gen): ...`, `fix(core): ...`)
- A brief description in the PR of what changed and why
