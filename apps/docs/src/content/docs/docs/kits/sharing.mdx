```
├── hyperdev-package.config.js   # HyperDev package configuration
├── README.md                    # Usage documentation
├── CHANGELOG.md                 # Version history
├── LICENSE                      # Legal terms
├── templates/                   # Template collection
│   ├── component/
│   │   ├── template.yml
│   │   └── *.jig
│   ├── service/
│   │   ├── template.yml

│   ├── validation.ts

│   ├── guides/
│   └── examples/
└── tests/                       # Template validation tests

```

## Publishing to NPM

<Steps>
1. **Prepare Package**
    Validate and prepare your template package:
    
    ```bash
    # Validate package structure and metadata
    bun run lint && bun test
    
    # Test all templates
    bun run test
    
    # Build optimized package
    bun run build
    ```
  
2. **Version Management**
    Use semantic versioning for clear upgrade paths:
    
    ```bash
    # Patch release (bug fixes)
    bun version patch
    
    # Minor release (new features)
    bun version minor
    
    # Major release (breaking changes)
    bun version major
    ```
  
3. **Publish**
    Publish to NPM registry:
    
    ```bash
    # Public package
    bun publish
    
    # Scoped package
    bun publish --access public
    
    # With distribution tag
    bun publish --tag beta
    ```
</Steps>

### Private Registry Setup

```bash
# Configure private registry
```

## Git-Based Distribution

### Direct Repository Sharing

```bash
# Install from GitHub repository
hyper add github:myorg/react-templates

# Install specific branch or tag
hyper add github:myorg/react-templates#v2.1.0
hyper add github:myorg/react-templates#develop

# Install from private repository
hyper add git+ssh://git@github.com/myorg/private-templates.git

# Use templates from repository
hyper gen component --from github:myorg/react-templates
```

### Repository Structure for Sharing

```
template-repository/
├── .hyperdev/                  # Repository configuration

├── README.md                   # Repository documentation
├── templates/                  # Template collection
│   ├── component/
│   ├── service/
```

```yaml
  autoRelease: true
  releasePattern: "v*"
```

### Automated Publishing with GitHub Actions

```yaml
# .github/workflows/release.yml
name: Release Templates

on:
  push:
    tags: ['v*']

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v1
      
      - name: Install dependencies
        run: bun install
        
      - name: Validate templates
        run: bun run lint && bun test
        
      - name: Run tests
        run: bun test
        
  publish:
    needs: validate
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v1
      
      - name: Configure NPM
        run: |
          echo "//registry.npmjs.org/:_authToken=${{ secrets.NPM_TOKEN }}" > ~/.npmrc
          
      - name: Publish to NPM
        run: bun publish
        
        
      - name: Create GitHub Release
        uses: actions/create-release@v1
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          tag_name: ${{ github.ref }}
          release_name: Release ${{ github.ref }}
```

## Troubleshooting Distribution Issues

  <details>
<summary>Template not found after installation</summary>

    **Symptoms**: `hyper gen` reports template not found despite successful installation
    
    **Solutions**:
    ```bash
    # Refresh template cache
    hyper config clear-cache clear
    
    # Verify installation
    hyper list --verbose
    
    # Check discovery paths
    hyper config get discovery.paths
    
    # Force re-discovery
    hyper refresh --all
    ```

  </details>

  <details>
<summary>Version conflicts between templates</summary>

    **Symptoms**: Conflicting dependencies or incompatible template versions
    
    **Solutions**:
    ```bash
    # Check dependency tree
    hyper deps --tree
    
    # Resolve conflicts
    hyper resolve-conflicts
    
    # Pin specific versions
    hyper pin @org/template 1.2.3
    
    # Use resolution overrides
    hyper config set resolutions.@org/template "1.2.3"
    ```

  </details>

  <details>
<summary>Private registry access issues</summary>

    **Symptoms**: Access failures when connecting to private registries
    
    **Solutions**:
    ```bash
    # Check registry configuration
    hyper config get registry
    
    # Verify network connectivity
    curl -I https://private-registry.com
    
    # Reset registry configuration
    hyper config unset registry
    ```

  </details>

<Aside type="caution">
