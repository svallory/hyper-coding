# Working with Worktrees

HQ has first-class support for git worktrees and integrates with [Worktrunk](https://github.com/max-sixty/worktrunk) (`wt`).

## Listing Worktrees

```bash
hyper hq list
```

```
Projects (/Users/you/work)
──────────────────────────────────────────────────
  my-api  (git, 3 worktrees)
    ├─ main *     /Users/you/work/my-api
    ├─ feat-auth  /Users/you/work/my-api.feat-auth
    └─ fix-deploy /Users/you/work/my-api.fix-deploy
  my-frontend  (git)
```

## Spawning on Worktrees

### Existing worktree

```bash
hyper hq launch my-api --worktree feat-auth
```

### New worktree

```bash
hyper hq launch my-api --new-worktree feat-payments
```

This runs `wt switch -c feat-payments`, then starts a Claude session in the freshly created directory.

## How It Integrates

| Operation | Tool used |
|-----------|-----------|
| List worktrees | `wt list --format=json` (fallback: `git worktree list --porcelain`) |
| Create worktree | `wt switch -c <branch>` |
| Path resolution | Respects Worktrunk's path template config |

## Without Worktrunk

No `wt` installed? HQ falls back to `git worktree list --porcelain` for listing. For creating new worktrees, run `git worktree add` yourself, then use `--worktree` to point HQ at it.
