Configure Claude Code to understand HyperDev's file formats and give you useful completions and explanations when working with `.jig` templates and recipe YAML.

## Prerequisites

- Claude Code installed (`npm install -g @anthropic-ai/claude-code` or via Homebrew)
- HyperDev repo cloned locally (`bun install` to set up dependencies)

## Associate .jig with a language

Claude Code inherits VS Code's file associations. Add this to your editor settings so `.jig` files get reasonable syntax highlighting:

```json settings.json
{
  "files.associations": {
    "*.jig": "html"
  }
}
```

HTML mode highlights the `{{ }}` delimiters and `@if`, `@each`, `@let` block tags well enough to be useful.

## CLAUDE.md configuration

Create a `CLAUDE.md` file at the repo root so Claude Code understands HyperDev's conventions from the start of every session:

```markdown CLAUDE.md
# HyperDev project

## Template engine: Jig
- Template files use the `.jig` extension (Jig engine, an Edge.js fork)
- Syntax: `{{ variable }}`, `{{ camelCase :: name }}` for filters
- Block tags: `@if(condition)/@end`, `@each(item in list)/@end`, `@let(x = expr)`
- The `@ai` tag triggers a second AI generation pass for that block at runtime
- YAML frontmatter controls output: `to:` (output path), `inject:`, `when:`, `after:`
- NEVER suggest EJS syntax (`<%= %>`) — this codebase uses Jig only

## Recipe YAML
- Recipes live in `recipes/` or inside kit directories
- A recipe is a YAML file with a `steps:` array
- Step tools: template, action, recipe, shell, prompt, ai, install, query, patch,
  ensure-dirs, sequence, parallel, conditional
- Steps can declare `depends_on:` for ordering and `exports:` to pipe outputs to later steps
- `when:` on any step is a Jig expression evaluated at runtime

## CLI commands
- `hyper gen <recipe> [--name=X]` — run a recipe
- `hyper run <kit> <recipe>` — run a recipe from an installed kit
- `hyper tools` — list available step types
- `hyper plan <recipe>` — dry run, shows what will be generated
- `hyper watch <recipe>` — re-run recipe on file changes
- `hyper kit install <source>` — install a kit from a local path or registry

## Trust system
- Recipes and kits can request permissions (file writes, shell commands, network access)
- Flag any recipe step that uses `shell:` with elevated privileges
- Never auto-approve shell steps that write outside the project root

## Package structure
- `@hypercli/core` — types, errors, parsers (no runtime deps on other packages)
- `@hypercli/kit` — kit lifecycle, source resolution
- `@hypercli/gen` — recipe engine, Jig templates, AI 2-pass
- `@hypercli/cli` — thin oclif shell, provides `hyper` binary
- Dependencies flow left-to-right only; no circular deps

## Package manager
- Always use `bun`, never npm or yarn
- `bun test` for tests, `bun run build` for builds
- `moon run <package>:<task>` to run tasks across the monorepo
```

## Useful Claude Code prompts for HyperDev

With `CLAUDE.md` in place, Claude Code understands the project context. Try prompts like:

- "Write a recipe that generates a Prisma model and its CRUD service"
- "Add an `@ai` block to this `.jig` template that infers prop types from the component name"
- "Explain what this recipe step does and whether it has any side effects"
- "Convert this shell script into a `shell` step inside a recipe"
- "This `.jig` file has an error — what's wrong with the frontmatter?"
- "What `exports:` would I need to pipe this step's output to the next template step?"

Claude Code will answer using actual HyperDev constructs rather than generic scaffolding advice.
