# Advanced Usage

Once you're past the basics, here's what HyperDev can do when you push it harder. This guide explains when and why to reach for each advanced feature. For full working examples with code, see [Advanced Patterns](/docs/examples/advanced-patterns).

## Multi-Step Recipe Composition

A single template generates a single file. When a feature spans multiple files — an API route, a React component, and their tests — you need a recipe that wires them together with `depends_on` and shared outputs.

Use multi-step recipes when the generated files have real dependencies between them (e.g., the component needs the API route's path). If the files are independent, batch generation (below) is simpler. The recipe engine resolves dependencies via topological sort and runs independent steps in parallel automatically.

See [Advanced Patterns — Multi-Template Recipes](/docs/examples/advanced-patterns#multi-template-recipes) for a complete recipe example.

## Template Inheritance

Define a base recipe with shared variables and steps, then `extends:` it in specialized recipes. This keeps your variable definitions DRY when you have a family of related generators (e.g., several component types that all need `name` and `styling` variables but differ in their steps).

Inheritance is worth introducing when you notice two or more recipes duplicating the same variable block. Until then, keep things flat.

## Batch Generation

Generate multiple items at once by looping over `hyper gen` in a shell script, or use a `shell` step inside a recipe to iterate over a data file. This is the right approach when you need to generate the same kind of artifact for a list of names — models, components, routes — without dependencies between them.

```bash
for name in UserCard ProfileCard SettingsCard; do
  hyper gen react-component --name=$name --output=./src/components/
done
```

## Watch Mode

Re-run a recipe automatically when source files change:

```bash
hyper watch recipes/api-route --on-change=src/models/**/*.ts
```

Use watch mode when you have generated code that must stay in sync with a source file — for example, regenerating API types whenever your Prisma schema changes. See [Advanced Patterns — Watch Mode](/docs/examples/advanced-patterns#watch-mode) for more detail.

## Dry Run with `hyper plan`

Before running a recipe, preview exactly what it will generate:

```bash
hyper plan fullstack-feature --name=Invoice
```

Shows each step, the files it would write, and whether any already exist. Nothing is written to disk. Good habit before running a recipe in an unfamiliar project or after editing a template.

## Configuration

### Source discovery

Point HyperDev at your template directories and trusted remote sources:

```javascript hypergen.config.js
export default {
  templates: ['recipes', 'cookbooks'],
  discovery: {
    sources: ['local', 'npm', 'workspace'],
    directories: ['recipes', 'cookbooks', '_templates'],
    exclude: ['node_modules', '.git', 'dist'],
  },
}
```

### Conflict strategy

Controls what happens when a generated file already exists:

```javascript hypergen.config.js
export default {
  output: {
    conflictStrategy: 'fail', // fail | overwrite | skip | merge
  },
  environments: {
    development: {
      output: { conflictStrategy: 'overwrite' },
    },
  },
}
```

`fail` is the safe default — you won't accidentally clobber a file you've edited by hand. Switch to `overwrite` in dev when you're iterating on the template itself.

## Template Testing

Templates are code; they should have tests. Create a test recipe that generates output and then runs the compiler and test suite against it. Run it in CI to catch template regressions before they merge.

## Debugging

### Show resolved config

```bash
hyper config show --verbose
```

### Debug recipe execution

```bash
DEBUG=hyperdev:* hyper gen react-component --name=Debug
```

### Profile slow generation

```bash
HYPERDEV_PROFILE=true hyper gen complex-recipe --name=Foo \
  --profile-output=./profiles/trace.json
```

Load `trace.json` in Chrome DevTools Performance tab to see where time is going.

## hyper dash

An interactive dashboard showing all available recipes, recent generation history, and kit status:

```bash
hyper dash
```

## hyper hq

Kit registry and management — install, update, and inspect the kits available in your project:

```bash
hyper hq
hyper kit install nextjs
hyper kit list
```
