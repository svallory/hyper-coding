# HyperDev CLI Reference

The `hyper` CLI is your main interface for running code generation. This page covers every command, option, and workflow.

<Aside type="note">
  This is the command reference for the `hyper` tool. For a higher-level overview, see the [CLI Overview](/docs/tools/cli-overview).
</Aside>

## Installation & Setup

### Installing HyperDev CLI

```bash
# Install via bun
bun add -g hyper

# Verify installation
hyper system version
```

### First Time Setup

```bash
# Initialize a generator workspace with examples
hyper init workspace --withExamples=true

# Create your first generator
hyper init generator --name=my-component --framework=react

# Discover available generators
hyper discover

# List available actions
hyper list
```

## CLI Design Philosophy

### Progressive Complexity
- **Basic**: Simple action execution and template discovery
- **Intermediate**: Recipe system for complex workflows
- **Advanced**: Configuration, custom generators, and power features

### Intelligent Discovery
Commands auto-discover generators and suggest alternatives when something isn't found:
```bash
hyper gen my-component  # Auto-discovers if not found
hyper list component    # Filters by category
hyper info button       # Shows detailed parameter info
```

### Safety First
Built-in guardrails prevent accidental overwrites:
```bash
hyper gen create-api --dryRun      # Preview changes first
hyper gen create-api --force       # Override safety checks when you mean it
```

## Core Commands

### Action Management

#### `hyper gen <name> [parameters...] [options]`

The primary command for code generation. Runs an action or recipe by name.

**Syntax:**
```bash
hyper gen <action-name|recipe-file> [--param=value] [--flag]
```

**Smart Action Resolution:**
HyperDev resolves actions in this order:
- Registered actions by name: `hyper gen create-component`
- Recipe files directly: `hyper gen my-component.yml`
- Auto-discovery: Searches for `.hyper/kits/<name>.yml` if nothing else matches

**Options:**
- `--defaults` - Use default values instead of prompting
- `--dryRun` - Preview changes without writing files
- `--force` - Force overwrite existing files
- `--<param>=<value>` - Set action/recipe parameters

**Examples:**

<Tabs>
  <TabItem label="Action Execution">
```bash
# Execute with parameters
hyper gen create-component --name=Button --type=tsx

# Use defaults for quick generation
hyper gen create-api --name=UserAPI --defaults

# Preview changes before applying
hyper gen create-component --name=Header --dryRun

# Force overwrite existing files
hyper gen update-schema --name=User --force
```
  </TabItem>
  <TabItem label="Recipe File Execution">
```bash
# Execute recipe file directly
hyper gen my-component.yml --name=Button --typescript=true

# Execute with dry run
hyper gen recipes/react-component.yml --name=Header --dryRun

# Auto-discovery of recipe files
hyper gen fullstack-app --name=MyApp --database=postgresql
# Searches for: fullstack-app.yml, .hyper/kits/fullstack-app.yml
```
  </TabItem>
  <TabItem label="Parameter Formats">
```bash
# String parameters
--name=MyComponent --path=src/components

# Boolean parameters  
--typescript=true --tests=false

# JSON parameters for complex values
--config='{"strict": true, "target": "es2020"}'
--options='["async", "export"]'

# Space-separated format
hyper gen create-api --name UserAPI --method GET
```
  </TabItem>
</Tabs>

**Error Handling:**
When an action fails, you get a specific error and suggestions:
```bash
❌ Action name required
   Code: ACTION_INVALID_PARAMETERS

💡 Suggestions:
   1. Provide action name
      Specify the action you want to execute
      $ hyper gen <action-name> [parameters...]

   2. List available actions
      See all available actions
      $ hyper list
```

### Generator Discovery

#### `hyper discover [sources...]`

Scans configured sources for generators and registers them.

**Sources:**
- `local` - Local generators in `recipes/` directory
- `npm` - Installed npm packages with generators
- `workspace` - Workspace-level generators

**Examples:**
```bash
# Discover from all sources
hyper discover

# Discover only local generators
hyper discover local

# Discover from specific sources
hyper discover local npm
```

**Output Format:**
```
🔍 Discovery complete: found 12 generators

Generators found:
  📦 react-component (local)
     Path: recipes/react-component
     Actions: create, update, test
     Description: React component generator with TypeScript

  📦 express-api (npm)  
     Path: node_modules/@hypercli/express-api
     Actions: create-endpoint, create-middleware
     Description: Express.js API generator
```

### Recipe System (V8 Features)

<Aside type="note">
  **New in V8**: The Recipe System enables multi-step code generation workflows with dependency management, progress tracking, and solid error handling.
</Aside>

Recipes are YAML files that chain multiple generation steps together. Each step can use a different tool (template, action, codemod, recipe), and steps can depend on each other.

#### `hyper recipe execute <recipe> [options...]`

Runs a recipe end-to-end with live progress output.

**Syntax:**
```bash
hyper recipe execute <recipe.yml> [--var=value] [--flag]
```

**Options:**
- `--dryRun` - Preview all changes without writing files
- `--force` - Force overwrite existing files
- `--skipPrompts` - Use defaults, skip interactive prompts  
- `--continueOnError` - Keep going after step failures
- `--<variable>=<value>` - Set recipe variables

**Real-time Progress:**
```bash
📈 setup-database: initializing (10%)
✅ Step: setup-database (1250ms)
📈 create-api: generating (45%)
✅ Step: create-api (2100ms)
📈 create-frontend: processing (78%)
✅ Step: create-frontend (1800ms)
```

**Examples:**

<Tabs>
  <TabItem label="Basic Execution">
```bash
# Execute a recipe with variables
hyper recipe execute fullstack-app.yml --name=MyApp --database=postgresql

# Preview recipe execution
hyper recipe execute api-service.yml --name=UserService --dryRun

# Execute with error handling
hyper recipe execute complex-setup.yml --continueOnError --force
```
  </TabItem>
  <TabItem label="Advanced Execution">
```bash
# Execute with complex variables
hyper recipe execute microservice.yml \
  --name=AuthService \
  --features='["jwt", "oauth", "2fa"]' \
  --env=production \
  --continueOnError

# Execute with progress callbacks
hyper recipe execute deployment.yml \
  --environment=staging \
  --skipPrompts \
  --force
```
  </TabItem>
  <TabItem label="Error Recovery">
```bash
# Continue execution after failures
hyper recipe execute migration.yml --continueOnError

# Force execution with file overwrites
hyper recipe execute setup.yml --force --skipPrompts
```
  </TabItem>
</Tabs>

**Execution Results:**
```bash
✅ Recipe 'Fullstack App' completed successfully

Execution Summary:
  Duration: 4250ms
  Steps completed: 5/5
  Failed steps: 0
  Skipped steps: 0
```

#### `hyper recipe validate <recipe>`

Checks a recipe file for syntax issues, missing dependencies, and bad references.

**What it checks:**
- YAML syntax
- Required fields (name, steps, variables)
- Variable type definitions and constraints
- Step dependency validity and circular references
- Tool availability and configuration
- Template file references
- Sub-recipe existence

**Examples:**
```bash
# Validate recipe syntax
hyper recipe validate my-recipe.yml

# Validate with detailed output
hyper recipe validate recipes/fullstack-app.yml
```

**Successful Validation:**

### Step Management

Step commands let you inspect and run individual steps within a recipe---handy for debugging or selective re-execution.

#### `hyper step list <recipe>`

Lists every step in a recipe with its dependencies, conditions, and tool config.

**Syntax:**
```bash
hyper step list <recipe-path>
```

**Examples:**
```bash
# List steps in recipe
hyper step list my-recipe.yml

# List steps with full details
hyper step list .hyper/kits/fullstack-app.yml
```

**Detailed Output Format:**
```bash
📋 Steps in recipe: Fullstack App (8)

1. validate-inputs
   Description: Validate all input parameters
   Tool: action
   Action: input-validator
   Continue on error: false

2. setup-project-structure
   Description: Create basic project directories  
   Tool: template
   Template: project/structure.jig
   Depends on: validate-inputs

3. generate-database-schema
   Description: Create database migration files
   Tool: template
   Template: database/postgresql-schema.sql.jig
   Condition: database === 'postgresql'
   Depends on: setup-project-structure
   Continue on error: true

4. generate-api-server
   Description: Generate Express.js API server
   Tool: action
   Action: express-generator
   Depends on: generate-database-schema

5. generate-frontend-app
   Description: Generate React frontend application  
   Tool: recipe
   Sub-recipe: react-app.yml
   Depends on: generate-api-server

6. setup-testing
   Description: Configure testing framework
   Tool: template
   Template: testing/jest-config.jig
   Depends on: generate-frontend-app
```

Each step entry includes: name, description, tool type (template, action, recipe, codemod), tool-specific config, dependency chain, execution conditions, and error handling behavior.

#### `hyper step execute <recipe> <step-name> [options...]`

Runs a single step from a recipe in isolation.

**Syntax:**
```bash
hyper step execute <recipe-path> <step-name> [--var=value] [--flag]
```

**Options:**
- `--dryRun` - Preview step execution without making changes
- `--force` - Force execution even with dependency issues
- `--<variable>=<value>` - Set step variables

**Examples:**

<Tabs>
  <TabItem label="Basic Step Execution">
```bash
# Execute specific step
hyper step execute fullstack-app.yml setup-database --database=postgresql

# Preview step execution
hyper step execute api-service.yml create-endpoints --dryRun

# Execute with variables
hyper step execute component.yml generate-component --name=Button --typescript=true
```
  </TabItem>
  <TabItem label="Advanced Step Execution">
```bash
# Execute step with complex variables
hyper step execute microservice.yml generate-api \
  --name=UserService \
  --endpoints='["users", "auth", "profile"]' \
  --dryRun

# Force step execution (skip dependency checks)
hyper step execute complex-recipe.yml build-step --force

# Execute with debug information
hyper step execute workflow.yml validation-step --debug
```
  </TabItem>
</Tabs>

**Step Execution Results:**
```bash
✅ Step 'generate-api-server' completed successfully
  Duration: 2100ms
  Files created: src/api/server.js, src/api/routes/users.js
  Files modified: package.json

# Or with dry run:
🔍 [DRY RUN] Step 'generate-api-server' would complete successfully
  Duration: 1200ms
  Files would be created: src/api/server.js, src/api/routes/users.js
  Files would be modified: package.json
```

**Dependency Handling:**
```bash
❌ Step execution failed: generate-frontend-app
  Missing dependency: generate-api-server must be completed first
  
💡 Suggestion: Execute the full recipe or run dependency steps first:
  $ hyper step execute fullstack-app.yml generate-api-server
  $ hyper step execute fullstack-app.yml generate-frontend-app
```

<Aside type="caution">
  **Dependencies**: When running individual steps, their dependencies need to be satisfied first. Use `hyper step list <recipe>` to review the dependency chain.
</Aside>

### Project Initialization

#### `hyper init generator [options...]`

Scaffolds a new generator with the standard structure.

**Options:**
- `--name=<name>` - Generator name (required)
- `--description=<desc>` - Generator description
- `--category=<category>` - Generator category [default: custom]
- `--author=<author>` - Author name
- `--directory=<dir>` - Output directory [default: recipes]
- `--type=<type>` - Generator type: action, template, both [default: both]
- `--framework=<framework>` - Target framework: react, vue, node, cli, api, generic [default: generic]
- `--withExamples=<boolean>` - Include example templates [default: true]
- `--withTests=<boolean>` - Include test templates [default: true]

**Examples:**
```bash
# Create a basic generator
hyper init generator --name=my-widget

# Create a React component generator
hyper init generator --name=react-component --framework=react --category=component

# Create an API generator without examples
hyper init generator --name=api-endpoint --framework=node --withExamples=false
```

#### `hyper init workspace [options...]`

Sets up a generator workspace, optionally with examples.

**Options:**
- `--directory=<dir>` - Workspace directory [default: recipes]
- `--withExamples=<boolean>` - Include example generators [default: true]

**Examples:**
```bash
# Initialize workspace with examples
hyper init workspace

# Initialize clean workspace
hyper init workspace --withExamples=false --directory=generators
```

## Advanced Usage Patterns

### Parameter Passing Strategies


### Automation & Scripting

```bash
#!/bin/bash
# Automated project setup script

set -e

echo "Setting up fullstack project..."

# Initialize workspace
hyper init workspace

# Generate API layer
hyper recipe execute api-layer.yml --name="$1" --database=postgresql --force

# Generate frontend
hyper recipe execute react-frontend.yml --name="$1" --api-url="http://localhost:3000"

# Generate tests
hyper gen create-tests --name="$1" --type=integration

echo "Project $1 setup complete!"
```

### Error Handling & Recovery

```bash
# Continue execution despite step failures
hyper recipe execute complex-setup.yml --continueOnError

# Validate before execution
if hyper recipe validate my-recipe.yml; then
  hyper recipe execute my-recipe.yml --name=MyProject
else
  echo "Recipe validation failed"
  exit 1
fi

# Dry run for safety
hyper gen risky-operation --dryRun || {
  echo "Dry run revealed issues, aborting"
  exit 1
}
```

## Troubleshooting

### Common Issues

**Action Not Found**
```bash
$ hyper gen my-component
❌ Action 'my-component' not found

# Solutions:
hyper discover              # Rediscover generators
hyper list                  # See available actions
hyper list component        # Filter by category
```

**Template Validation Errors**
```bash
$ hyper template validate template.yml
❌ Template validation failed:
  • Missing required field: name
  • Invalid variable type: config.timeout

# Solutions:
# 1. Fix template.yml syntax
# 2. Check variable definitions
# 3. Validate against schema
```

**Recipe Execution Failures**
```bash
$ hyper recipe execute broken-recipe.yml
❌ Recipe execution failed: Step 2 failed

# Solutions:
hyper recipe validate broken-recipe.yml  # Check syntax
hyper step list broken-recipe.yml        # Review steps
hyper recipe execute broken-recipe.yml --continueOnError  # Skip failures
```

### CI/CD Integration

```yaml
# .github/workflows/validate-templates.yml
name: Validate Templates
on: [push, pull_request]

jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: oven-sh/setup-bun@v1
      
      - name: Install HyperDev
        run: bun add -g hyper
        
      - name: Validate Templates
        run: |
          find recipes/ -name "template.yml" -exec hyper template validate {} \;
          
      - name: Validate Recipes  
        run: |
          find recipes/ -name "*.yml" -path "*/recipes/*" -exec hyper recipe validate {} \;
```


### Naming Conventions

- **Actions**: `verb-noun` (create-component, update-schema)  
- **Templates**: `technology-type` (react-component, express-api)
- **Recipes**: `descriptive-name` (fullstack-app, microservice-setup)
- **Parameters**: `camelCase` (componentName, apiEndpoint)

### Error Handling

Validate inputs and give recipes a clear recovery path:

```yaml
# recipe.yml
name: "Safe Recipe"
steps:
  - name: "validate-inputs"
    tool: "action"
    action: "validate-config"
    continueOnError: false
    
  - name: "backup-existing"  
    tool: "action"
    action: "backup-files"
    condition: "!dryRun"
    
  - name: "generate-code"
    tool: "template"
    template: "component.jig"
    continueOnError: true
```
